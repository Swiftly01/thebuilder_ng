# Legacy-removal audit

Boundary: candidate application code, clean migrations, production Composer lock and registered routes. The old `/backend` and private archives are preservation material, excluded from deployment.

The candidate came from an official skeleton and fresh lock. No historical migration/model/controller directory was copied. The only selective port is pure TOTP logic, moved into Identity and tested against an RFC 6238 vector, timestep replay and recovery behavior.

No ticket, ticket-type, sponsor, volunteer, registration, payment, QR/PDF or old compatibility module exists in the candidate. Approved sponsored editorial labels, ad campaigns and the disabled `editorial_events` listing are distinct Builder capabilities. Stock Laravel optional driver configuration is framework scaffolding; production requires database cache/queue/session and public media storage, without Redis/S3 packages.

Packaging uses a positive source list and fresh locked production dependency installation. Old backend files, .migration-archive, environments, local databases/fixtures/credentials, backups, tests and frontend dependencies are excluded. Final scan evidence belongs in the testing report.

The active `/backend` still contains the preserved legacy application because source-data and hosted-staging gates remain incomplete. A clean candidate is not completed cutover. Archive the old backend and promote the candidate only after those gates pass.
